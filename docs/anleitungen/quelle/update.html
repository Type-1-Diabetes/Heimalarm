Schritt 1 · Apps

5 min
  1. PC: Heimalarm öffnen (Symbol im Infobereich unten rechts). Auf Start erscheint „Heimalarm x ist verfügbar“ → Installieren. Die App startet danach neu.
  2. Handy: App öffnen → Installieren → im Android-Fenster Aktualisieren. Fragt Android nach „Apps aus dieser Quelle zulassen“: erlauben und noch einmal tippen.
Geklappt, wenn Einstellungen › Darstellung & Updates die neue Version zeigt.

Schritt 2 · Zentrale auf dem Raspberry Pi

  1. Per SSH auf den Pi und eingeben: 
    cd ~/Heimalarm && git pull && cd zentrale
cp -r ../esp32/* esp32/
docker compose up -d --build
    cp holt die neue ESP32-Vorlage in zentrale/esp32 – daraus baut ESPHome. Ohne den Schritt spielt ESPHome weiter die alte Firmware auf. secrets.yaml bleibt erhalten; eine eigene Kennung (nicht ich) danach in der Board-Datei wieder eintragen. Meldet git pull „local changes would be overwritten“: die genannte Datei sichern, mit git checkout -- <datei> zurücksetzen, noch einmal git pull.
Geklappt, wenn docker compose ps den Dienst als running zeigt. Weiter mit Schritt 3.
{{i:server}}

Schritt 2 · Zentrale auf der UGREEN NAS

15 min
  1. Dateien holen: GitHub Type-1-Diabetes/Heimalarm → Code → Download ZIP, am PC entpacken.
  2. Versteckte Dateien zeigen: in Dateien unten links auf das Zahnrad → „Versteckte Dateien anzeigen“. Sonst siehst du die .env nicht.
  3. Hochladen nach docker/heimalarm: den Inhalt von zentrale (docker-compose.yml, dienst, mosquitto …) und den ganzen Ordner esp32. Bei der Frage immer Ersetzen.Wird docker-compose.yml nicht ersetzt, laufen alte Teile weiter – z. B. die entfernte Tuya-Brücke.
  4. ESPHome wieder einschalten: docker-compose.yml mit TextEdit öffnen, beim Abschnitt esphome: die Zeile profiles: ["esphome"] löschen, speichern.Die neue Datei bringt die Zeile jedes Mal wieder mit. Die Docker-App beachtet Profile aus der .env nicht.
  5. Alten Dienst entfernen: Docker › Container → heimalarm-dienst-1 stoppen und löschen. Images → heimalarm-dienst löschen.Sonst nimmt die NAS die alte Version wieder.
  6. Neu bauen: Projekte › heimalarm → Neu bereitstellen. Das Fenster offen lassen, bis alle Zeilen „Running“ zeigen (1–3 min).
  7. Aufräumen: Gibt es noch Container oder Images, die nicht mehr in der docker-compose.yml stehen (z. B. tuya-bruecke), diese und ihren Ordner löschen.
{{i:warn}}
Nie ersetzen oder löschen: .env, mosquitto/data, dienst/data, esp32/secrets.yaml. Darin stehen Passwörter, Kopplungen und gespeicherte Nachrichten.
Geklappt, wenn die App unter Einstellungen › Zentrale die neue Version des Zentrale-Programms zeigt. Steht dort noch die alte: die App am PC einmal ganz beenden (Rechtsklick auf das Symbol → Beenden) und neu öffnen.

Schritt 3 · ESP32 (nur bei neuer Firmware)

15 min
  1. ESPHome starten: NAS: Container › heimalarm-esphome-1 → Start. Pi: docker compose --profile esphome up -d esphomePi: vorher Schritt 2 mit dem cp-Befehl gemacht? Sonst baut ESPHome die alte Firmware.
  2. Im Browser http://<IP der Zentrale>:6052 öffnen, anmelden mit heimalarm und deinem MQTT_PASSWORD.
  3. Die richtige Karte wählen: Alle Karten heißen alarm-ich und zeigen „Online“. Entscheidend ist die Datei unter dem Namen: alarm-ich-s3.yaml (ESP32-S3), alarm-ich.yaml (ESP32) oder alarm-ich-d1mini.yaml (D1 mini). Die beiden anderen ⋮ → Löschen.
  4. Auf deiner Karte ⋮ → Validieren. Erwartet: „Konfiguration ist gültig!“
  5. Installieren (blauer Pfeil) → Im Netzwerk. Beim ersten Mal 5–15 min.
  6. ESPHome wieder stoppen – wird nur zum Bauen gebraucht.
{{i:info}}
Nie die Datei eines anderen Boards aufspielen. Weil alle gleich heißen, schickt ESPHome sie trotzdem an deinen ESP32 – danach geht er nur noch per Kabel zu retten.
Geklappt, wenn im Protokoll „Connected“ und „Boot seems successful“ stehen. Die LED pulsiert kurz blau, leuchtet 3 s grün und geht aus. In der App Einstellungen › Melder (ESP32) › LED am ESP32 steht „Farbige LED erkannt“.

Optional · Eigenes Konto für den Melder

10 min

Bisher meldet sich der ESP32 mit demselben Konto an wie App und Zentrale. Wer dieses Passwort aus dem Melder ausliest, könnte alles steuern. Mit einem eigenen Konto darf der Melder nur Alarme melden und keine Firmware-Updates auslösen. Ohne diesen Schritt läuft alles weiter wie bisher.

  1. Neues Passwort ausdenken: lang, nur Buchstaben und Ziffern, z. B. 25 Zeichen.Kein $: Docker liest $ in der .env als Platzhalter, die Zentrale speichert dann ein anderes Passwort.
  2. .env der Zentrale öffnen (NAS: Dateien › docker › heimalarm, Pi: nano ~/Heimalarm/zentrale/.env) und unten eine neue Zeile anfügen: 
    MQTT_ESP_PASSWORD=dein-neues-passwort
    MQTT_USER=heimalarm und MQTT_PASSWORD bleiben unverändert – das ist weiter das Konto für App und Zentrale.
  3. Zentrale neu starten: NAS: Projekte › heimalarm → Neu bereitstellen. Pi: cd ~/Heimalarm/zentrale && docker compose up -d
  4. secrets.yaml (NAS: docker/heimalarm/esp32, Pi: zentrale/esp32) – nur diese zwei Zeilen ändern, nicht doppelt eintragen: 
    mqtt_user: "heimalarm-esp"
mqtt_pw: "dein-neues-passwort"
  5. ESP32 neu aufspielen wie in Schritt 3 (Installieren → Im Netzwerk).
Geklappt, wenn auf Start „Alle Verbindungen ok“ und „ESP32 online“ stehen und der Kontakt-Test auf „geschlossen“ springt. In der App selbst ändert sich nichts.
